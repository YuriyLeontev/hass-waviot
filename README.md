Кастомная интеграция для счётчиков электроэнергии WAVIoT (NB-IoT, FOBOS и т.п.) через облачный API `lk.waviot.ru`.

> ⚠️ Неофициальная интеграция, не связана с компанией WAVIoT.

## Что умеет

- Автоматически находит каналы учёта счётчика (сумма + тарифы T1–T4) и создаёт сенсоры `kWh` с `state_class: total_increasing` — готовы для Energy dashboard.
- **Импортирует почасовую историю показаний в long-term statistics HA** (statistic id вида `waviot:<MODEM>_electro_ac_p_lsum`). При первом запуске подтягивает всю историю, которую отдаёт API: запрос идёт окнами по 30 дней назад, пока показания не закончатся (у счётчиков это обычно больше года — сервер хранит собственный профиль нагрузки, иногда с даты до установки). Это даёт точную статистику по дням/часам, даже если HA был выключен или счётчик прислал данные с задержкой (для NB-IoT это норма).
- **Расчёт стоимости** по тарифам (день/ночь): при заданной цене импортирует параллельные статистики `..._cost` с той же почасовой привязкой. Цену можно менять с даты (`t1@01.10.2026=7.86`) — каждый час считается по тарифу, который действовал именно в этот час.
- Диагностика: напряжение батарейки, температура устройства, время последнего выхода на связь.
- Настройка через UI (config flow), опрос каждые 30 минут.

## Установка

### Через HACS (рекомендуется)

1. HACS → ⋮ → **Custom repositories** → добавьте URL этого репозитория, категория **Integration**.
2. Найдите **WAVIoT** в списке HACS и установите.
3. Перезапустите Home Assistant.

### Вручную

1. Скопируйте папку `custom_components/waviot` в каталог конфигурации HA:
   `<config>/custom_components/waviot/`
2. Перезапустите Home Assistant.

### Настройка

**Настройки → Устройства и службы → Добавить интеграцию → WAVIoT.** Введите:
- **API-ключ** — со страницы API в личном кабинете lk.waviot.ru;
- **ID модема** — HEX-номер модема (виден в ЛК, например `<MODEM>`);
- базовый URL менять не нужно (`https://lk.waviot.ru`).

## Energy dashboard (статистика по дням)

**Настройки → Панели → Энергия → Потребление из сети → Добавить.**

Выберите один из двух источников:
- `waviot:<modem>_electro_ac_p_lsum` — внешняя статистика с точной почасовой историей (**рекомендуется**);
- или сенсор `sensor.waviot_<modem>_energy_total` — обычный сенсор (статистика начнёт накапливаться с момента установки и привязана ко времени опроса).

Если счётчик многотарифный, добавьте `..._t1` и `..._t2` как два отдельных источника и пропишите для каждого свою цену — HA сам посчитает расходы по тарифам.

## Опции

Шестерёнка на карточке интеграции:
- **Каналы** — список через запятую, если автоопределение нашло не всё, например: `electro_ac_p_lsum_t1,electro_ac_p_lsum_t2` (узнать точные имена каналов можно скриптом `waviot_discover.py`);
- **Цены** — тарифы для расчёта стоимости, например `t1=6.97,t2=3.86` (день/ночь). Шорткаты `t1..t4`, `tsum`, `total` разворачиваются в имена каналов; десятичный разделитель — точка (см. [Повышение тарифа с даты](#повышение-тарифа-с-даты));
- **Импорт статистики** — можно выключить, если нужны только «живые» сенсоры.

### Повышение тарифа с даты

Тарифы меняются (обычно с 1 января и 1 июля), а пересчитывать всю историю по новой цене нельзя. Поэтому цена задаётся списком периодов: к записи добавляется дата через `@`, начиная с 00:00 которой действует новая цена.

```
t1=6.97,t2=3.86,t1@01.10.2026=7.86,t2@01.10.2026=4.35
```

Здесь до 1 октября 2026 года день считается по 6.97, ночь по 3.86, а с 1 октября — по 7.86 и 4.35. Каждый час потребления умножается на тариф, действовавший именно в этот час, поэтому уже накопленная статистика не «переоценивается».

- дата — локальная, в формате `01.10.2026` или `2026-10-01`; можно задать сколько угодно периодов (`t1=5.0,t1@01.07.2025=6.0,t1@01.10.2026=7.0`);
- запись без даты — стартовая цена; она же применяется ко всему, что было до первой даты;
- если цены пишутся с запятой (`6,97`), разделяйте пары точкой с запятой: `t1=6,97; t1@01.10.2026=7,86`;
- новую цену удобно вписать заранее — она включится сама в нужный день;
- **после любого изменения цен статистика стоимости (`..._cost`) пересчитывается заново** — по всей истории, которая есть в HA: пересчёт идёт из уже импортированной статистики кВт·ч, без обращений к API. Поэтому период, добавленный задним числом, тоже учтётся. Статистика в кВт·ч при этом не трогается.

### Стоимость в Energy dashboard

Для внешних статистик HA не умеет считать деньги сам, поэтому интеграция импортирует отдельные статистики стоимости. Задайте цены в опциях, затем в Energy dashboard для источника энергии выберите «Отслеживание затрат» → **Использовать объект, отслеживающий общие расходы** → статистику `... cost`.

## waviot_discover.py

Разовый скрипт для разведки (запускать на любом Debian, только stdlib):

```bash
python3 waviot_discover.py --key <API> --modem <MODEM>
python3 waviot_discover.py --key <API> --modem <MODEM> --raw   # сырой JSON get_values
```

Показывает информацию о модеме, какие registrators есть в `get_values` и какие каналы реально отдают данные.

## Заметки

- Глубина первого импорта не задана константой: обход останавливается после трёх подряд пустых окон (месячная тишина счётчика его не обрывает) либо на потолке в 5 лет. Проверить, сколько истории отдаёт ваш счётчик, можно скриптом `waviot_discover.py` — он печатает первую точку и длину периода.
- Счётчик NB-IoT выходит на связь редко (обычно раз в 1–6 часов), поэтому «живое» значение сенсора может отставать — это нормально, импорт статистики ставит показания в правильные часы задним числом.
- При сбросе/замене счётчика отрицательная дельта показаний игнорируется (sum не ломается).
- Если API-ключ скомпрометирован — перегенерируйте его в ЛК и обновите интеграцию (удалить/добавить заново).
